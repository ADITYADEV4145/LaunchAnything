product source references remain relative to the upstream repository at the linked
revision. Source README text inside a scan may describe historical upstream tests;
those are not launch outcomes or measurements made by this showcase.

### Submit your kit and results

An owner or authorized maintainer can open an issue or pull request with:

- Explicit permission to name the product and redistribute the submitted copy,
  screenshots, media and results, plus an explanation of their authority to grant it.
- A public repository URL and pinned revision, the Liftoff commands/version used,
  elapsed time and any platform limitations or manual substitutions.
- A sanitized kit: grounded `product.json`, `plan.md`, brief, posts, check output,
  review HTML and reasonably sized media. Do not include tokens, account details,
  private user data, local machine paths or approval credentials.
- A `README.md` with a **Results** section. If unlaunched, say
  **not launched yet, no real results — pending**. After launch, supply public post
  links, observation dates/windows and evidence for any reported metrics. Distinguish
  measured observations from goals, and do not attribute causality without evidence.

The maintainer will review permission and evidence before listing a product. No
permission is inferred from an open-source license alone; no results are invented
to fill an empty slot. See the [historical case studies](../docs/case-studies/groundwork.md)
for additional process context, not launch outcomes.
